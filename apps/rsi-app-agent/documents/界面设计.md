# 界面设计

> 展开[原则](原则.md)第 8、9 节。平台界面在 `console/web/`，各应用的 web 应用在 home 里的 `<应用>/code/web/`（业务页面在 `web/views/`）。

## 结构

左栏三组一级入口，按权限过滤，看不到的不显示：

1. **使用**（最上面）：每个能用的应用一项，`/use/<应用>/...`。应用自己的界面；没有就用通用任务视图。管理者在这里有“管理此应用”的入口。
2. **应用管理**：`/manage`，我管理的应用卡片（任务、待处理问题、待批提案、使用人数）和 AI 编码会话；带待处理计数。
3. **系统管理**：用户、用户组、角色，各自要求对应的系统权限。

底部是 harness 与执行器状态、当前用户（修改密码、退出）。顶栏是面包屑。

## 应用管理：进入后用页签

`/manage/<应用>/<页签>`。页头是应用名、稳定版、“打开应用”和“AI 修改”。

| 页签 | 回答什么 |
|---|---|
| 应用包与代码 | 任一版本的文件树。Markdown 可预览或看源码；代码用编辑器并带补全；表格、文档、演示文稿、图片、音视频可预览或播放。稳定版上可以改多个文件、上传、删除，一起提交成提案 |
| 改进信号 | 字段修正、区域或整单的改进建议，以及对界面、功能的建议，归成问题（界面建议按区域或页面归并，每个新功能单独一条）。点开看当时整张单据的输入、输出、材料和附件。可以 AI 修改、手动修正，或不采纳（要写原因，提出的人看得到） |
| 提案 | 改动差异（含二进制的放入和删除）、决策记录、五道闸门、开发集 / 留出集前后对比；可以试用候选版本、对它评测；按应用的批准规则由一位或两位管理者批准或驳回；批准就是发布，规则改为一位后已有一位批准的提案点“确认发布” |
| 评测 | 四个页签。结果：选版本（含候选版本）跑评测，版本 × 用例矩阵，点开看逐项期望与实际；评测记录里“所选”标出只跑了部分用例的评测（不作为发布依据）；每次评测可下载 Markdown / JSON 报告。用例：按标签筛选、勾选多个用例选版本“运行所选”；编辑用例时一并维护输入、期望、验证规则、验证程序、标签，下方是用例文件夹的文件和历次结果；可从已确认的真实单据生成。文件：评测集文件库，和代码包同一套查看、编辑、上传。规则说明：评测规范、评测时怎么用、结果怎么看 |
| 版本与发布 | 新版本上线的五步（改 → 候选版本 → 试用和评测 → 验证 → 批准）；任意两个版本对比；各版本得分；设为稳定版；存储方式（本机或 MinIO）和内容寻址说明 |
| 权限 | 选用户或用户组，授“使用”或“管理”；没有合适的组可以就地新建；下面列出实际有权限的每个人和权限来源 |

## AI 编码

- **新建应用** `/manage/new`：只填名称、标识和目标需求，进入会话。
- **会话** `/manage/build/<id>`：左边对话（助手的每一步工具调用都列出来，可以停止），右边是文件树（按知识 / 代码 / 契约 / 评测着色，本次改过的标“新”）。文件用同一套查看器：可预览、可编辑、可上传、可改名、可删除。检查、测试、改动三个页签在旁边。检查通过后可以发布；表格和文档随其他改动进入提案。
- **助手的约定在界面上看得见**：助手每轮自己检查、测试，测试页签显示“助手自动测试”和所测用例；助手缺材料时，对话里出现上传卡片（要什么、为什么、放到哪个用例），上传后点“上传好了，告诉助手”，或点“暂时没有”；输入框左边的回形针可以随手上传文件给助手（放进 `evals/inbox/`）。改动页签把评测用例的改动单列，发布时由你确认保存；别人中途在评测页改过的用例标“冲突”，不能覆盖。
- **预览**：页头“预览”按钮或“预览”页签，用工作区当前的文件打开应用自己的界面（没有界面的应用用通用任务视图），可以建单据、修正、确认、执行动作，像正式使用一样试。预览单据只留在会话里，版本一栏显示“工作区”，不成为改进信号；助手改完一轮自动刷新，也可以手动重新加载或清空预览单据。
- **已有应用的“AI 修改”**在“应用包与代码”页签里，和会话是同一套对话栏与工作区（同一个组件，样式和交互一致）。对话栏默认折叠成左侧一条窄栏，点开或点页头“AI 修改”展开；第一条消息从稳定版开出一个会话（地址带 `?build=<id>`），页面换成这个会话的工作区：对话、文件、检查、测试、改动，发布成提案。可以“回到版本浏览”，对话保留，展开对话栏时列在“继续之前的对话”里。
- **栏宽**：对话栏、文件树、文件内容三栏之间的分隔线可以横向拖动，双击还原；宽度记在本浏览器里，会话页和应用包页共用。
- **全屏**：会话页面、应用包页（还没开始对话时在页头，对话中在工作区右上角）都有全屏按钮；在应用包页里开始对话、回到版本浏览时保持全屏。全屏铺满整个窗口（隐藏侧边栏和应用页头），Esc 或再点一次退出；编辑器和弹窗里的 Esc 不会触发退出。改进信号里点“AI 修改”直接进入这个工作区。

## 系统管理

- **用户**：姓名、账号、职务、系统角色、所在用户组、各应用的权限；可停用。
- **用户组**：成员和它在各应用上的授权。
- **角色**：内置“系统管理员”“应用开发者”不可改；自定义角色勾选系统权限。

## 报关应用的业务界面

- **单据列表**：一屏看全，按“待我处理 / 需补充 / 已确认 / 全部”筛选，可搜单号、客户、提单号、合同号。每行：摘要与材料数、客户、提单号、运输 / 成交、件数 / 毛重、商品行数、状态、最高风险、修正数、所用版本、经办、时间。列表上方是本人修正的去向。
- **新建报关单**：拖入材料，按文件名猜类型（可改）；选业务类型（提取制单 / 审单 / 校验）和委托客户；客户列表来自以前单据里用过的客户。
- **单据详情**：顶部是步骤（材料 → 提取 → 审核 → 确认 → 草单）和操作（提建议、重新提取、确认、生成草单、下载）。左边原件，右边结果：已提的建议、风险条、需要补充的问题（可直接补材料重新提取）、按技能阶段分组的表头、可展开的表体、本票修改记录、执行记录。点任何值就地修改并选范围；每个分组标题上可以对这一块提建议，页头可以对整单提建议。字段名上停留看依据。有未解决的 P0 / P1 风险时，确认要二次确认。
- **试用条**：管理者可以切到别的版本。试用时顶上标明版本，单据单独存放，不成为改进信号；界面也是那个版本打包出来的。

## 不装作有能力

- 找不到 harness：AI 编码页顶部直说，发消息的按钮给出原因。
- 没配模型：提案器的 AI 起草显示原因并给出手动路径。
- 执行不可用：harness 未接入时，侧栏、评测页直说，单据执行如实失败并写明原因。
- 登录：账号 + 密码；系统管理 › 用户里新建用户要设初始密码，每行可重置密码，没有密码的用户标“未设密码”。
