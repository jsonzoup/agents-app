# 应用包规范

> 展开[原则](原则.md)第 4、5 节。

一个应用是 home 目录下的一个文件夹，文件夹名就是 `app.json` 的 `name`：

```
<home>/<app>/
├── code/                          应用本身；版本只快照它
│   ├── app.json                   清单（契约级）
│   ├── AGENTS.md                  给智能体的总说明（知识级）
│   ├── scopes/<键>/<值>/AGENTS.md  范围知识，如某个客户（知识级）
│   ├── skills/<名>/               Agent Skills：SKILL.md、references/（知识级）、scripts/（代码级）；拷贝进来，不链接
│   ├── .mcp.json                  外部系统，标准 MCP 服务器配置；密钥只写成 `${环境变量名}`（契约级）
│   ├── contract/                  输入、输出 JSON Schema（契约级）
│   └── web/                       应用自己的 web 应用：全栈 Next.js 项目，带自己的 .env。列入 evolve.code 后是代码级，否则是契约级；.env 永远是契约级
└── evals/                         怎么评判它，按评测规范 rsi-eval/1；不进版本，智能体看不到，只由人改或确认
    ├── eval.json                  评测集清单：规范版本、其他验证程序、标签
    ├── cases/<id>/                一个用例一个文件夹：case.json、input/ 输入材料、可选 expected/
    ├── judge/server.ts、mcp.ts    默认验证程序（裁判）MCP 服务，只给内核用；mcp.ts 是内核那份零依赖 MCP 服务的拷贝
    └── tests/*.test.ts            可选：应用自测，代码级提案必须通过
```

## app.json

| 字段 | 含义 |
|---|---|
| `name`、`title`、`description` | 标识与说明 |
| `task.input` / `task.output` | 输入、输出 Schema 路径 |
| `task.statuses` | 任务允许的终态，如 `["result","pause"]` |
| `agent.instructions` / `skills` / `entry` / `mcp` | 交给执行器的说明、技能、入口技能、MCP 配置 |
| `scopes[]` | `{key, title, from}`；`from` 是任务输入里的路径，如 `input.customer.code` |
| `evolve.knowledge` / `evolve.code` | 可进化文件的 glob。覆盖到契约文件时，加载即报错 |
| `evals.cases` / `holdout` | 用例目录、留出集用例 id；路径相对 `evals/` |
| `judge.command` / `args` | 启动裁判 MCP 服务的命令，在 `evals/` 里运行 |
| `web` | 应用自己的 web 应用目录，如 `"web"`；没有就用平台的通用任务视图 |
| `actions` | 业务动作，如生成草单：`{title, command, args, input, output, requiresConfirmed}`。`args` 里的 `{input}`、`{output}` 换成临时文件；`input` 是工作结果里的点路径；在单据所用版本的目录里运行 |

`code/` 里的路径都相对 `code/`。无论清单怎么写，`app.json`、`.mcp.json`、`contract/**`、任何 `.env`/`.env.*` 永远是契约级；没被 `evolve` 声明的文件也按契约级处理。web 应用要进化，就把 `web/**` 写进 `evolve.code`。版本快照里没有 `node_modules`、`.next` 和除 `.mcp.json`、`.gitignore`、`.env*` 以外的点文件。`evals/` 不进应用版本，不分级；人每次保存评测集，内核记一个快照 `eN`。

## 用例

用例的目录、`case.json` 字段、声明式规则、验证程序、打分、运行与报告格式见[评测规范](评测规范.md)。简述：

```json
{
  "id": "A",
  "title": "一句话说明",
  "tags": ["smoke"],
  "input": { "...": "符合 contract/input.schema.json；材料写成 <app>/evals/cases/A/input/x.pdf" },
  "expected": { "...": "应用自定，验证程序负责解释" },
  "rules": [{ "path": "status", "op": "equals", "value": "result" }],
  "source": "期望值出自哪里",
  "split": "dev"
}
```

`split` 可省略：`app.json` 的 `evals.holdout` 名单里的是留出集，其余是开发集。名单本身是契约，只能随契约一起改。在评测页保存用例时，从上传区引用的材料会复制进 `evals/cases/<编号>/input/`。可选的 `evals/expect.ts` 从已确认单据起草用例：标准输入是 `{input, output}`，标准输出是裁判要的期望值。期望值只能由人改，或由人确认 AI 编码助手起草的改动。

## 裁判（默认验证程序）

一个 MCP 服务（任何 MCP SDK 都行；创建应用时平台把内核那份零依赖的 `mcp-server.ts` 拷成 `evals/judge/mcp.ts`），提供两个工具：

- `score(case, run)` → 逐项检查 `[{path, ok, expected, actual}]`，内核据此算分。
- `check(run)` → 不变量违例列表（字符串）。任一违例都会挡住发布。

裁判跑在 `evals/` 里，不在任何版本里，所以进化改不到它。它要读应用的契约文件时读源 `../code/`。其他验证程序同样是 MCP 服务，在 `eval.json` 的 `validators` 里声明，用例用 `validator` 选。

## 自测

- `evals/tests/*.test.ts` 用 `node --test` 跑，环境变量 `RSI_APP_CODE` 指向候选版本的代码目录（手动运行时缺省为 `../code`）。

## web 应用 web/

一个完整的 Next.js 项目：页面、服务端接口（连数据库、调外部接口、调大模型、存对象存储）、自己的依赖和 `.env`。新应用从 `builder/templates/web/` 开始，平台的组件库、改进组件和 SDK 类型复制进 `components/`、`sdk/`，应用自己就能构建。

运行：平台按 `(应用, 版本)` 在 `<home>/.rsi/web/` 下各构建一次——依赖按 `package.json` + 锁文件安装一次、复制进每个构建；`next build` 时注入 `RSI_BASE_PATH=/apps/<应用>/v/<版本>`（工作区预览是 `/apps/<应用>/w/<会话>`）、`NEXT_PUBLIC_RSI_API`、`NEXT_PUBLIC_RSI_APP`、`NEXT_PUBLIC_RSI_VERSION`；再在本机回环地址上 `next start`。`/apps/...` 的请求先过平台的登录和权限检查，去掉平台的会话 Cookie，加上 `x-rsi-user-id`、`x-rsi-user-name`、`x-rsi-user-roles` 后转给它。应用进程只拿到运行 node 所需的环境变量和它自己的 `.env`，拿不到平台的密钥。处理任务的智能体拿到的版本目录里没有 `web/`；学习者也看不到 `.env`（契约级）。

`views/index.tsx` 默认导出一个 React 组件，收到 `AppUiProps`（`sdk/index.ts`，平台 `console/web/src/sdk` 的副本）：

| 属性 | 含义 |
|---|---|
| `app` | 应用摘要：标题、稳定版本、当前用户在这个应用的权限级别（`use` / `manage`）与具体权限、声明的动作、范围 |
| `user` | 当前用户 |
| `path` / `navigate` | `/use/<应用>/` 之后的路径段，应用自己决定子页面 |
| `api` | `HostApi`：单据的列表、新建、重跑、修正、确认、动作，上传，本人修正的去向，材料与产物的地址。服务端按权限检查每次调用 |

组件：`@/components/ui/*`（shadcn/ui）和 `@/components/kit`。`EditableValue` 就地改一个值并选范围；`SuggestButton` 对一块区域或整张单据提建议（可附截图、表格），服务端把单据的输入、输出和已有修正一起存进信号；它也能提对界面（`target.level: "ui"`，所在页面自动带上）和新功能（`"feature"`）的建议，这两种不分范围、不需要单据，由 `api.suggestApp` 提交，归成问题后交给编码助手改 `web/`。平台在每个应用页顶部另有一个“提建议”，所以应用自己没放入口时也能提；`SuggestionList` 列出这张单据上的建议；`ContributionBanner` 是本人修正的去向。修正时 `path` 是工作结果里的点路径（写回用），`field` 是信号里的字段名（归并问题用），两者都由应用决定。`api.suggest` 提交建议。`api.version` 平时是 `null`（稳定版）；试用时是正在试用的版本。浏览器里经 `lib/rsi.ts` 调平台接口（同源，带本人的会话）；自己的服务端接口用 `appUrl("api/...")`；服务端代码用 `lib/caller.ts` 取调用人。

## 导出与导入

“版本与发布”页可以选一个版本导出压缩包：`<应用>/code/**`（含 `web/.env`，只有管理者能导出）、`<应用>/evals/**`（当前评测集）和 `<应用>/rsi-export.json`（版本、指纹、评测集快照、导出人）。导入压缩包会开一个 AI 编码会话：应用标识没被占用就是新应用，否则是这个应用基于稳定版的修改；照常检查、测试，由人发布。
