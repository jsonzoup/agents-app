# 报关应用 customs-declaration

> 第一个垂直应用，住在 home 的 `customs-declaration/` 里（本仓库用的 home 是 `baoguandan-agent/testhome`）。行业词汇只出现在那里和本文。

## 它由什么组成

`code/` 下：

| 部分 | 位置 | 级别 |
|---|---|---|
| 能力 | `skills/customs-extraction`：拷贝自 customs-extraction-skill 仓库（不含 `__pycache__`），之后随本应用进化 | 知识级（`SKILL.md`、`references/`）、代码级（`scripts/`） |
| 应用说明 | `AGENTS.md`：禁填字段、每个值写 `reason`、P0/P1 暂停 | 知识级 |
| 客户知识 | `scopes/customer/913101156073392545/AGENTS.md`：联合汽车电子有限公司的身份信息 | 知识级 |
| 契约 | `contract/input.schema.json`（材料 + 可选客户 + 可选的报关员指定值：`bill_no` 提运单号、`supervision_method` 监管方式、`business_type` 业务类型、`message` 留言、`instructions` Copilot 指令记录）、`contract/output.schema.json`（`declaration` 引用技能的输出 Schema，加 `risks`、`questions`）；技能输出 Schema 新增表体 `origin` 原产地证明组（7 栏）。`instructions` 与 `origin` 是工作区 b-mv4mzc5ng4a9 的契约草稿，发布要人决定 | 契约级 |
| 旧系统口径 | 技能 `references/operator-hints.md`（留言只有字面值覆盖、五项确认按位、4 位关区代码、5/6 位境内目的地、申报单位不作收货人证据）、`references/known-layouts.md`（Samsung、Nexperia、Murata、Infineon、TI、KOA、Bosch 版式与近铁等货代）；`direct-field-extraction.md` 补了合同号、境内收发货人、提单号的来源顺序和规格型号槽位保真。均提炼自 `baoguandanluru/specs`，不含货号、订单号、发票号等契约外字段 | 知识级 |
| 界面 | `web/`（页面在 `web/views/`）：单据列表、新建报关单（含指定值和留言）、单据详情（原件对照：PDF、图片、Excel 按工作表预览；报关员指定值；分组表头、表体、食品/危险品/集装箱分组、风险、补充材料、确认、草单；导出 Excel/JSON）；`web/views/layout.json` 表头按技能阶段 3–7 分组（共 54 项），表体是阶段 8，条件分组是阶段 9。按《报关灵 2.0 产品评审》补了：7 态任务状态（接收中、处理中、待补充、待确认、待接续、可交付、已交付，`model.ts` 的 `stageOf`）；详情页五道关导航（读得准、对得上、补得全、算得对、过得去，`checks.ts` 把 AI 风险和页面核对归到各关）；算得对的页面核对（数量×单价≠总价可一键改、净重>毛重、件数、法定千克数量合计对净重、多币制）和改数量/单价后的总价联动提示；对得上的商品行对应表（`rowmap.tsx`，从字段依据整理每行引用了哪份材料哪一处）；读得准的重复文件（sha256）与难读格式标注；右侧常驻 Copilot（`copilot.tsx`，文字或语音指令 → 带全部指令重新处理，指令即调整记录）；草单预览（合并单元格、附表）；原件预览（`preview.tsx`）支持 PDF、图片（含多页 TIFF，可缩放旋转）、Excel/CSV/ODS、Word（docx）、PowerPoint（pptx）、Markdown、网页（沙箱）和纯文本（UTF-8 或 GBK，JSON 自动排版），doc/ppt/wps/ofd/heic 等提示另存后重传；成交方式与运保费的跨字段核对（CIF 不报运保费，C&F 报保费，C&I 报运费，FOB/EXW 两项都报，缺项不自动补 0.3%，技能 `audit-rules.md` 同规则）；页面核对未清的单据不进"可交付"；重新提取、补充材料、Copilot 处理后提示 AI 改了哪些字段（前 → 后）和风险条数变化；本票有人工修改时重新处理前先确认；确认弹窗同时列出未解决风险和页面核对提示 | 契约级 |
| 动作 | `app.json` 的 `actions.draft`：确认后用技能的 `render_customs_draft.py` 生成进口报关草单 xlsx；模板换成产品给的版本，含「进口报关草单附表」（申报地海关、启运时间、目的地海关、清单类型，以及食品、许可证、危险品、原产地证明、集装箱五段，行不够时插行并保持页脚行高） | 契约级 |

`evals/` 下（不进版本，只由人改）：

| 部分 | 位置 |
|---|---|
| 材料 | `cases/{A,B,C,D}/input/`：拷贝自技能仓库 `tests/fixtures`，用例里附 `sha256` |
| 用例 | `cases/{A,B,C,D}`：期望值抄自技能验收测试里的断言；C 是留出集 |
| 裁判 | `judge/server.ts`：`score` 逐项比对；`check` 查多余字段、字段集合与顺序、禁填字段、缺 `reason`、净重大于毛重、单价×数量≠总价、暂停与 P0/P1 不一致。字段集合读源 `../code/skills/customs-extraction/schemas/output.schema.json` |
| 自测 | `tests/app.test.ts`：候选版本的技能脚本是合法 Python、契约与技能里的 JSON 能解析、`SKILL.md` 引用的文件都在 |

客户范围从任务输入的 `customer.code`（统一社会信用代码）读取。旧系统里“货号取前 10 位”“订单号以 55 开头”等客户规则涉及契约外字段，恢复它们要人改契约，不能由进化循环加。

和旧系统（`baoguandanluru`）相比仍未做的：OCR 流水线和置信度/坐标（改为多模态直读和逐字段 `reason`）；货号、商品英文名、发票号、发票日期、订单号；企业库、商品库、RAG 映射、舱单查询；第三方异步接口与回调、欧坚格式；Word、邮件、压缩包材料；表头 `境内收发货人-10位检验检疫编码` 和表体 `货物属性`、`用途`、`生产日期`。其中字段类的要人改契约和评测。

对照《报关灵 2.0 产品评审》仍未做的：原件坐标定位与逐字段置信度；按工厂拆单、混装拆分（Copilot 会忽略这类契约外指令）；改一处只增量重核相关字段（现在是页面核对实时重算，AI 侧仍整票重跑）；HS 预归类与历史归类比对；客户经验库是平台级能力，应用内只用客户 scope 的 `AGENTS.md`。Copilot 重新处理会清掉本票已有的修改（修改已作为信号记录）。

## 版本谱系：单价规则

技能仓库的真实历史里，`单价` 这一行规则改过两次。r1–r3 是用真实内核按这段历史重建的三个版本：

| 版本 | 单价规则 | 出处 | 开发集 |
|---|---|---|---|
| r1 | 固定留空，由下游计算 | 技能文档 issue 17 第 230 行 | 1/3 |
| r2 | 总价 ÷ 数量，6 位小数去尾零 | 决策记录第 30 行 + 开发日志第 17 行，重建 | 2/3（B 的 0.101 对不上期望的 0.1010） |
| r3 | 总价 ÷ 数量，固定 4 位小数 | 技能当前第 131 行；重建时逐文件核对与 `code/` 一致 | 3/3 |

两次变更都以“人提交的提案”进入：信号由“业务方（决策记录回放）”记录，提案附真实决策记录，经验证、闸门、批准后发布。

**局限**：只重建了单价这一行，脚本和其他规则用的是今天的版本；所有版本都按今天的期望评分；B 的期望值后来被人改过；当时的批准人不可考。

## 执行

单据和评测都由 `rsi-harness` 的 `headlessExecutor` 在版本目录里起 `dsh` 执行：智能体读版本里的说明和技能，材料路径由平台换成绝对路径。harness 不可用时执行如实失败。r1–r5 当时的评测和单据由已移除的模拟执行器产生，记录保持原样（运行里的执行器字段写着当时用的是什么）；要看真实表现，对版本重新跑评测、对单据重新执行。
